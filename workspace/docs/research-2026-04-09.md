# AAOS on Raspberry Pi — Upstream Research Snapshot

**Captured:** 2026-04-09

> **Historical snapshot.** Upstream pins below are still current
> (`android-16.0.0_r4`, `bp4a`). The VM sizing mentioned here (20 cores,
> 192 GiB) is not — it is now 48 vCPU / 200 GiB. See `CLAUDE.md`.

## AOSP release

- **Latest public tag:** `android-16.0.0_r4` (Android 16 QPR2).
- Google moved AOSP publishing to a **biannual Q2 / Q4 cadence** in
  2026. The next drop is expected Q2 2026.
- The lunch suffix changed from `bp2a` (under `_r1`) to **`bp4a`**
  with `_r4`. Any older guide or script that still uses `bp2a` will
  fail for `_r4`.

## Canonical upstream for Pi

Two GitHub organisations matter:

1. **`raspberry-vanilla/*`** — KonstaKANG's Pi port of AOSP. The
   `android_local_manifest` repo (branch `android-16.0`) is the
   authoritative list of Pi-specific projects pinned against AOSP
   `_r4`.
2. **`noahchalifour/aaos-rpi`** — thin wrapper around raspberry-vanilla
   that bundles all 6 lunch targets (tablet / TV / car × Pi 4 / Pi 5)
   and ships `rpi{4,5}-mkimg.sh`. Currently also uses `android-16.0`
   branch of raspberry-vanilla.

We pull straight from raspberry-vanilla to stay closer to upstream.

| Path | Repo |

| `device/brcm/rpi4`          | `raspberry-vanilla/android_device_brcm_rpi4` |
| `device/brcm/rpi5`          | `raspberry-vanilla/android_device_brcm_rpi5` |
| `device/brcm/rpi4-kernel`   | `raspberry-vanilla/android_device_brcm_rpi4-kernel` |
| `device/brcm/rpi5-kernel`   | `raspberry-vanilla/android_device_brcm_rpi5-kernel` |
| `vendor/brcm`               | `raspberry-vanilla/proprietary_vendor_brcm` (shared) |

Plus ALSA, libcamera + libpisp, FFmpeg, Mesa / DRM / minigbm, codec
projects — all on `android-16.0`.

**Kernel is precompiled** (Image + DTB + overlays shipped in
`device/brcm/rpi{4,5}-kernel`). No kernel build step is needed during
the AOSP build. If you want to rebuild the kernel yourself, use
`raspberry-vanilla/android_kernel_manifest @ android-16.0` which
points at `common-android16-6.12-lts`.

## Component versions (April 2026)

- **Linux kernel:** 6.12 LTS — 6.12.60 in the vanilla Dec 2025 drop;
  6.12.67 in the March 2026 community (KonstaKANG / RaspAnd) respin.
- **Mesa:** 25.3.1
- **libcamera:** 0.6.0
- **FFmpeg:** 8.0.1
- **Security patch level:** Dec 5 2025 (vanilla) / Jan 1 2026 (community)

## Host environment

- **OS:** Ubuntu 22.04 LTS (canonical per raspberry-vanilla README)
- **Packages beyond stock AOSP prereqs:** `dosfstools e2fsprogs fdisk
  kpartx mtools rsync` + OpenJDK 17
- **Reasonable minimum:** 16 cores, 32 GiB RAM, 500 GiB SSD. We spec
  more (20 cores, 192 GiB, 600 GiB) because this Mac Pro has it.
- macOS hosts cannot build AOSP directly: APFS is case-insensitive by
  default and AOSP requires case-sensitive. Hence the Lima VM.

## Automotive specifics (or lack thereof)

**There is no Pi-specific automotive device tree in raspberry-vanilla.**
The `_car` lunch targets apply AOSP's standard automotive product
configuration on top of the same `rpi{4,5}` device tree. Practical
implications:

- **VHAL is the mock emulator** (`automotive.vehicle@V1-emulator-service`).
  No real vehicle bus integration out of the box.
- The usual automotive services ship as part of the `_car` product
  config: audio control, display framework, EVS mock, automotive
  launcher, automotive SELinux policy.
- If you need real CAN / LIN / vehicle network, that's a custom
  project on top of this baseline.

## Hardware support

**Supported:** Pi 4B / Pi 400 / CM4 and Pi 5 / Pi 500 / CM5. All need
≥2 GiB RAM.

**Working:** WiFi, Bluetooth, HDMI, DSI, touchscreens, USB, GPIO,
HW-accelerated graphics, H.265 decode, HDMI-CEC, most sensors,
libcamera cameras.

**Caveats:**
- CSI camera modules have "various issues" (upstream wording).
- SELinux is **permissive** by default on both boards.
- **No userdata encryption.**
- No GSM modem, no voice calls, no SMS.
- Display resolution in `BoardConfig.mk` must match the panel or the
  device won't POST — no fallback to a generic mode.
